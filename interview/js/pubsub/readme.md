## 发布订阅者模式
常用的设计模式的一种。定义了一种一对多的依赖关系，让多个订阅者通过事件中心（listeners）监听发布者的消息，实现对象之间的解耦通信。
抖音|哔哩哔哩 平台，存着订阅者们和发布者的事件中心，不需要发布者一个一个和订阅者交流

## 观察者模式
对象间一对多的依赖关系，目标状态发生改变时自动通知并更新所有观察者。
和订阅发布者模式很像
两者都基于事件机制，旨在实现对象间的一对多通信。当一方状态改变时，依赖方会自动收到通知并更新，从而实现松耦合。
- 两者的区别
    发布订阅者通过事件中心转发消息，发布者不直接联系订阅者，观察者是对象直接订阅目标，变化时被直接通知
    发布者订阅模式：像用微信订阅公众号，公众号发消息到“平台”，平台再推送给你，公众号根本不知道你是谁
    观察者模式：像你关注周杰伦，他一发动态直接通知你，是你和他之间的直接关系

    发布订阅中间多了一层中介（事件中心），观察者是直接盯着目标。
