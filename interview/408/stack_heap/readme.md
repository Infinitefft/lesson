# stack_heap

## 首先，我想结合JS内存模型来回答
    - 栈主要用于存储执行上下文、基本类型和函数调用，由系统自动管理。
    - 堆主要用于存储对象、数组、函数等引用的复杂数据，由开发者（new 申请内存 delete释放内存）或 GC（Garbage Collection 垃圾回收）管理
    栈里存的是简单类型值或引用地址  操作快
    堆里存的是对象的真实数据  不连续，还有碎片

    - 垃圾回收：标记清除、引用计数
    打扫卫生， 断舍离  贴个标签，没贴的就扔掉回收
    有人用 +1
    - 性能差异 栈快（只需要挪指针），堆慢
    栈连续内存（LIFO，无需GC），堆非连续（随机分配，需要GC）
    - 闭包，本该在栈释放的数据，被引用到了堆中

## 其次，数据结构的常客
- 栈是线性数据结构，LIFO
- 堆（大顶堆、小顶堆）树状，非线性数据结构，排序

## 总结
栈和堆的核心区别在于存储内容和管理方式。栈主要用于存储执行上下文和基本数据类型，由系统自动分配和释放，效率很高；堆主要用于存储对象等引用类型数据、由垃圾回收机制管理。

在JS中，变量本身在栈中，而对象实际存在堆中，栈里存的是指向堆的引用地址

栈的特点是内存连续，后进先出，访问速度快；而堆是动态分配的，可能产生碎片，访问相对慢。从声明周期来看，栈中的数据随着函数执行结束自动释放，而堆中的数据只要引用就不会被回收。

会影响浅拷贝、闭包以及内存泄露等问题


## 怎么判断对象是否可回收

对象是否可回收，取决于：是否还能被访问（是否可达）

``` js
function fn1() {
    let obj = { a: 1 };  // 会被回收
}
fn();


let gloablObj;
function fn2() {
    let obj = { a: 1 };  // 不会被回收
    gloabalObj = obj;
}
fn2();


let a = {};
let b = {};
a.x = b;
b.y = a;
// 循环引用
a = null;
b = null;

function outer() {
    let obj = { a: 1 };
    return function inner() {
        console.log(obj);
    }
}
let fn3 = outer();
```

## 什么是内存泄露
本该被回收的内存，因被意外引用而无法释放，导致占用持续增长，最终引发页面卡顿甚至崩溃
- 定时器未清理
    react 组件卸载了，但是定时器取消
    定时器内部函数引用外部变量，变量被长期的引用
- 时间监听未移除
- DOM引用未释放
    let el = document.getElementById('app');
    document.body.removeChild(el);
    el = null;
- 全局变量/意外挂载到全局
    var  window，永远是root 可到达的
- 闭包导致的内存泄露
- Map/Set 使用不当
    Map 和 json 的区别 obj 可以作为key
    obj = null，由于Map对他强引用，obj 不会释放
    WeakMap, WeakSet  key obj 被回收，自动回收，弱引用关系
- 订阅发布者模式
    不取消订阅，一直引用
- Promise 一直不结束
- api请求发起了，但结果还未到达，组件卸载了
